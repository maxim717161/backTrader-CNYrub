# backTrader-CNYrub

Минутная история квартального фьючерса на курс китайский юань – российский рубль с Московской биржи. Ряд собран так, чтобы дальше гонять на нём трендовую стратегию в backtrader.

Фьючерс торгуется с апреля 2022 года. Более ранней истории на бирже нет.

## Какие контракты входят в ряд

Нужен не весь срок жизни каждого выпуска, а кусок, на котором он ближайший к экспирации и поэтому обычно самый ликвидный. У квартального цикла это около трёх месяцев.

Коды контрактов: `CR` + месяц (`H` март, `M` июнь, `U` сентябрь, `Z` декабрь) + последняя цифра года. Пример: `CRZ5` — это `CNY-12.25`.

Окно каждого контракта:

- начало — следующий календарный день после последнего дня торгов предыдущего контракта;
- у самого первого выпуска, `CRM2`, начало — первый день торгов, 21 апреля 2022;
- конец — последний день торгов этого контракта;
- у контракта, который торгуется сейчас, конец — день загрузки.

Вечный фьючерс `CNYRUBF`, календарные спреды и контракты `UCNY` / `MOEXCNY` в ряд не входят: это другие инструменты. Дальние кварталы, которые ещё не стали ближайшими, тоже не качаются.

Время свечей — московское, как его отдаёт биржа, без перевода в UTC. Цена — рубли за 1 юань. Объём — число контрактов. Лот контракта — 1000 юаней.

Контракты не склеиваются. У каждого свой файл. История начинается на месяц раньше экспирации предыдущего выпуска, поэтому соседние файлы пересекаются по времени. У `CRM2` добавлять нечего: торги начались 21 апреля 2022.

## Откуда данные

Публичный ISS Московской биржи, ключ не нужен:

`https://iss.moex.com/iss/engines/futures/markets/forts/boards/RFUD/securities/{SECID}/candles.json`

Интервал `1` — одна минута. Запросы идут с паузой, готовые контракты при повторном запуске берутся из локального кэша. У текущего контракта окно каждый день удлиняется, поэтому он скачивается заново.

## Как запустить

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
python -m cnyrub contracts
python -m cnyrub download
```

Полезные флаги загрузки:

- `--force` — скачать все окна заново;
- `--workers 4` — число параллельных контрактов;
- `--today YYYY-MM-DD` — зафиксировать конец текущего окна, удобно для повторяемого прогона.

На 21 сентября 2026 в `data/bars/` лежат 19 контрактов, от `CRM2` до текущего `CRZ6`. Конец `CRZ6` в этом снимке — 21 сентября 2026, не дата его экспирации.

Поле `value` биржа по этим фьючерсам отдаёт нулём. Объём в контрактах заполнен.

После загрузки:

- `data/contracts.json` — все найденные выпуски CNY, фронтальное окно и `history_start`;
- `data/bars/{SECID}.parquet` — минутки одного контракта.

Колонки parquet: `datetime`, `end`, `open`, `high`, `low`, `close`, `volume`, `value`, `secid`. Поле `value` биржа по этим фьючерсам часто отдаёт нулём; объём при этом заполнен.

Проверки: `pytest`.

## Проверка стратегии

```bash
python backtest.py
```

Канал считается по закрытиям минуток каждого контракта. `python backtest.py --grid` перебирает длину окна 15, 30, 60, 120, 240, 480, 960, 2400 и 4800 минут. По правилу «обе половины контрактов в плюсе и во второй половине не меньше 4 сделок на контракт» на снимке 21 сентября 2026 выбрано окно 960 минут, выход 480. Обычный запуск гоняет его: вход на следующем открытии, если объём минуты сигнала не ниже медианы окна, стоп в 2,5 минутного диапазона. В последний день позиция закрывается и новая не открывается. Истории соседних контрактов пересекаются на месяц, поэтому сумма результатов — не один счёт.

## График

```bash
python plot.py
```

Скрипт читает `data/bars` и пишет `cny_front.png`: у каждого контракта своя линия дневного закрытия и объёма, линии между выпусками не соединяются. `--show` открывает окно, `--output` меняет путь к файлу.
