CNY/RUB: живая стратегия для Yandex Cloud Functions
====================================================

ВНИМАНИЕ. Каждый обычный вызов функции торгует РЕАЛЬНЫЙ счёт Т-Инвестиций.
Песочницы нет. Безопасны только вызовы с "probe": true и "fill_per_minute": 0.

Что в архиве
------------
README.txt                 этот файл
requirements.txt           зависимость одна: boto3
function/index.py          точка входа function.index.handler
src/cnyrub/                движок, брокер, состояние, уведомления ВК

Создание функции
----------------
  yc serverless function version create \
    --function-name cnyrub \
    --runtime python312 \
    --entrypoint function.index.handler \
    --memory 256m \
    --execution-timeout 60s \
    --source-path yandex/cnyrub-function.zip \
    --environment STATE_BUCKET=<бакет> \
    --environment AWS_ACCESS_KEY_ID=<ключ> \
    --environment AWS_SECRET_ACCESS_KEY=<секрет> \
    --environment VK_TOKEN=<ключ доступа сообщества> \
    --environment VK_USER_ID=<ваш id в ВК>

Окружение функции
-----------------
STATE_BUCKET             бакет Object Storage; один JSON на стратегию и счёт:
                         state/<стратегия>-<счёт>.json
                         и короткий файл позиции peers/<стратегия>.json
AWS_ACCESS_KEY_ID        статический ключ бакета
AWS_SECRET_ACCESS_KEY    секрет статического ключа
VK_TOKEN                 ключ доступа сообщества ВК с правом на сообщения
VK_USER_ID               личный диалог (сначала сами напишите сообществу)
VK_PEER_ID               беседа: 2000000000 плюс номер беседы (необязательно)
                         Если ВК не настроен, сделки просто сохраняются.
                         Сбой ВК сделку не отменяет.

Сервисному аккаунту функции нужен доступ на чтение к Lockbox (если токен
хранится там) и запись в бакет. Повторы таймера лучше выключить.

Стратегии (поле strategy)
-------------------------
short       окно 525 минут, выход по каналу 525, стоп 285 руб.
long        окно 12 420 минут, стоп 22 медианы, откат до половины
thirty      окно 30 минут, стоп 8, плечо 4, фильтры прямоты и громкости
fortyfive   окно 45 минут, стоп 8, плечо 4
sixty       окно 60 минут, стоп 8, плечо 5
momentum    дневной моментум, L = 20, H = 5, плечо 3. Не входит в запрет окон.

Защита от тонкого рынка (по умолчанию включена)
  thirty, fortyfive, sixty: min_stop 0.008, cooldown 15, skip_flat true.
  long: min_stop 0.008, skip_flat true, без паузы. short: без изменений.
  Выходные не торгуются: минутки субботы и воскресенья не попадают ни в окно,
  ни в историю (weekends: false). Если по выходным открыта позиция, стоп
  проверится по первой минутке понедельника.
  Откуда числа: 0.008 — 10-й процентиль дистанции стопа в будни по окнам 30, 45
  и 60. Комиссия в расчётах 5 руб. за контракт в каждую сторону, тик 0.001 стоит
  1 руб., так что круг комиссии равен 10 тикам, и стоп в 8 тиков комиссию не
  покрывает. Если нужен запас, поднимите min_stop.
  Пауза 15 минуток только разрывает цепочку «вход, стоп, вход» на одном уровне:
  по истории разные паузы от 5 до 120 минуток результат не различают.
  Отключить любую защиту: min_stop null, cooldown 0, skip_flat false, weekends true.

Одна стратегия: один отдельный счёт (или субсчёт). Позиция и капитал читаются
по всему счёту, две стратегии на одном счёте будут мешать друг другу.
Моментум — тоже свой субсчёт. Он не читает позицию окон и свою им не показывает.

Запрет ложного входа
--------------------
Правило то же, что в истории: «старшее, 2 дня, только плюс».
После шага стратегия пишет peers/<имя>.json: окно, позиция, цель, сколько
торговых дней позиция открыта и открытый результат. Чужую книгу с минутками
функция не читает.

Перед свежим входом смотрятся только более длинные окна. Если сосед уже два
торговых дня в плюсе и держит позицию против этого входа, цель снимается,
заявка не ставится. Фаза ответа veto, поле veto — имена соседей.
Своя позиция, стоп, выход и вход в ту же сторону не запрещаются.
Короткое окно длинное не глушит.
Моментум в этот обмен не входит: peers/<имя>.json он не пишет и не читает.

Счета остаются раздельными: файл соседа — подсказка, не общая позиция.
Если файл не прочитался или стратегии нет в бакете, вход не запрещается.
Остановка одного счёта не останавливает остальные. Две стратегии с одним
именем перезапишут один файл peers/<имя>.json.

Команды: JSON запуска
---------------------
Таймер: в payload кладётся JSON-объект. Тестовый вызов: тот же JSON, но
токен можно передать прямо полем token.

Обязательные поля
  strategy       short, long, thirty, fortyfive, sixty или momentum
  account_id     номер счёта Т-Инвестиций
  Токен берётся по порядку: поле token (тест), поле secret_id (id секрета Lockbox
  с ключом token или TOKEN), переменная окружения TOKEN. Последний способ — когда
  секрет Lockbox подключён к версии функции (раздел «Секреты Yandex Lockbox»,
  переменная TOKEN): тогда в payload таймера токен и secret_id не нужны.
  secret_id      id секрета Lockbox с ключом token или TOKEN
  token          токен Т-Инвестиций (только для тестового вызова)

Необязательные поля
  fill_per_minute  сколько контрактов менять за минуту
                   не указано или "auto" — не больше половины контрактов
                   на лучшей цене той стороны, которую съест заявка;
                   0 — пауза: заявки не ставятся, минутки копятся;
                   N > 0 — потолок N контрактов в минуту, стакан не читается
  reconcile        true — перезапуск после остановки (см. ниже)
  probe            true — только проба в ВК, заявка не ставится
  channel, exit_channel, loss_bars                    целые числа
  stop_mult, clock_cap, risk_fraction, stop_rub,
  breakout_span, scale_step, scale_back, scale_floor,
  eff_low, eff_high, surge_cap, leverage              числа; null отключает
  size_mode        режим размера позиции (flat или span)
  min_stop         наименьшая дистанция стопа в цене, 0.008 = 8 тиков
  cooldown         пауза после стопа в минутках, новых входов нет
  skip_flat        true — не входить, когда медианный диапазон окна нулевой
  weekends         true — торговать и считать окно по субботам и воскресеньям
  Поля параметров заменяют значение пресета стратегии. Без них работает пресет.

1. Рабочий запуск (таймер, каждую минуту сессии деривативов)
  С секретом, подключённым к функции как переменная TOKEN:
  {"strategy": "thirty", "account_id": "2254834906"}
  Либо с чтением Lockbox по id:
  {"strategy": "thirty", "account_id": "2254834906", "secret_id": "e6q..."}

2. Тестовый запуск с токеном (ТОРГУЕТ реальный счёт)
  {"strategy": "thirty", "account_id": "2254834906", "token": "t.xxxx"}

3. Проба: проверка бакета и ВК без заявки
  {"strategy": "thirty", "account_id": "2254834906", "token": "t.xxxx", "probe": true}
  Читает сохранённую книгу, шлёт в ВК стратегию, счёт, фазу, остановку,
  контракт, число минуток, позицию и цель. Биржу не спрашивает. Если бакет
  не читается, проба всё равно уходит с пометкой «книга не прочитана».
  В таймер probe не кладут: пока он включён, минута не торгует.

4. Пауза стратегии без остановки
  {"strategy": "thirty", "account_id": "2254834906", "secret_id": "e6q...", "fill_per_minute": 0}
  Фаза paused. Позиция не меняется, минутки продолжают накапливаться.
  Чтобы снять паузу, уберите поле из payload таймера.

5. Ограничить размер куска
  {"strategy": "thirty", "account_id": "2254834906", "secret_id": "e6q...", "fill_per_minute": 3}

6. Перезапуск после остановки (phase = halted)
  {"strategy": "thirty", "account_id": "2254834906", "token": "t.xxxx", "reconcile": true}
  Один разовый вызов. Читает позицию брокера, записывает её в книгу и снимает
  остановку, заявку не ставит (фаза reconciled). Перед этим откройте приложение
  брокера: после вызова истинной считается позиция у брокера. Если остановка
  была из-за неисполненной или неподтверждённой заявки, дождитесь, пока она
  исполнится или снимется. В таймер reconcile не кладут.

Фазы ответа (поле phase)
------------------------
history      докачивается история минуток, торговли ещё нет
catchup      подтягиваются пропущенные минутки
idle         новых минуток нет
hold         позиция равна цели
signal       цель изменилась, заявка пойдёт со следующей минуты
veto         свежий вход снят: старшее окно два торговых дня в плюсе против него
unfilled     заявка не исполнена (0 контрактов), остановки ещё нет
order        заявка исполнена (поле order: id, signed, executed, price, reason)
paused       fill_per_minute = 0
book         стакан не прочитан, минута пропущена
reconciled   выполнен перезапуск
probe        вызов с probe
halted       стратегия остановлена, поле halted содержит причину

Частичное исполнение
--------------------
Если брокер исполнил часть заявки (от 1 контракта до B-1), книга принимает ровно
столько, сколько исполнено, остановки нет. Остаток цель дозаберёт на следующих
минутах. В ВК в этом случае приходит строка «исполнено частично: A из B».
Если исполнено 0, стратегия НЕ останавливается: книга остаётся прежней (фаза
unfilled, поле unfilled — сколько раз подряд), а следующая минута заново решает,
нужна ли заявка. Остановка только после 10 нулевых исполнений подряд; любое
исполнение сбрасывает счётчик, перезапуск (reconcile) тоже. Остановка также при
исполнении больше заявленного и при неподтверждённой заявке.

Сбой запуска в ВК
-----------------
Если запуск упал с ошибкой (API не отвечает, бакет, Lockbox и т.п.), в ВК уходит
одно сообщение в сутки (по московской дате): стратегия, счёт, текст ошибки без
токена. Остальные сбои в этот день только пишутся в лог (phase = error).
Отметка лежит в бакете в alerts/<стратегия>-<счёт>.json. Запуск с reconcile
сбрасывает отметку: следующий сбой снова придёт в ВК. Если бакет недоступен,
отметка хранится в памяти процесса функции.

Сообщение об остановке в ВК
---------------------------
Когда стратегия останавливается, в ВК приходит одно сообщение: стратегия, счёт,
контракт, причина, позиция и цель. Повторные запуски в состоянии halted новых
сообщений не шлют. Снять остановку: запуск с reconcile (см. выше).

Причины остановки (поле halted) и что делать
--------------------------------------------
позиция на счёте X, в книге Y        позиция у брокера не совпала с книгой;
                                     проверьте счёт, затем reconcile
заявка не исполнена 10 раз подряд   биржа 10 минут подряд не исполняет заявки;
                                     проверьте счёт и активные заявки, затем reconcile
исполнено больше заявленного         проверьте счёт, затем reconcile
заявка не подтверждена               брокер не ответил на заявку; проверьте
                                     счёт и активные заявки, затем reconcile
контракт сменился, пока позиция      закройте позицию вручную в приложении,
ещё открыта                          затем reconcile
не хватает минуток, чтобы собрать    подождите, пока докачается история,
окно                                 затем reconcile
биржа не вернула гарантийное         повторите позже, затем reconcile
обеспечение

Ошибка «execution timeout exceeded»
-----------------------------------
Платформа сама убивает функцию, если она работает дольше таймаута. Проверьте:
1. Таймаут функции должен быть 60 с (--execution-timeout 60s). В консоли
   по умолчанию стоит 3 с: этого не хватает даже на загрузку boto3 и два запроса.
2. Память не меньше 256 МБ: на меньшей импорт boto3 в холодном запуске долгий.
3. У функции есть выход в интернет (не закрыта сеть и нет VPC без NAT): нужны
   storage.yandexcloud.net, invest-public-api.tbank.ru, api.vk.com, а для токена
   из Lockbox ещё payload.lockbox.api.cloud.yandex.net и 169.254.169.254.
Внутри функции есть предохранитель: через RUN_DEADLINE секунд (по умолчанию 45,
переменная окружения) запуск прерывается ошибкой «запуск не уложился в N с, этап:
...» (этапы: Lockbox, бакет чтение/запись, API <метод>, минута стратегии, ВК).
Ошибка идёт в лог и в суточное сообщение ВК. Если таймаут функции меньше 60 с,
поставьте RUN_DEADLINE на 5-10 с меньше него. Каждый успешный запуск пишет в лог
поле sec: сколько секунд он занял.

Лог
---
После каждого запуска функция пишет в лог одну строку JSON с тем же ответом:
strategy, account_id, phase, halted, order, secid, bars, held, target и,
если уведомление отправлялось, поле vk (отправлено, не отправлено, не настроено).
Если запуск упал, пишется строка с phase = error и текстом ошибки. Токен в лог
и в ответ не попадает.

Ограничения
-----------
Лимит функции 60 секунд; на все запросы к API отведено 45 секунд.
Идентификатор заявки (UUID) считается из стратегии и минуты: повтор той же
минуты не ставит вторую заявку.
Архив пересобирается командой: python -m function.pack
